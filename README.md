## V0.13按键与蜂鸣器

## V0.11目的和操作

V0.10正确日志已确认启动期屏端回读0C=50、0A=9C、0B=00，均status0/valid1/bytes1；有效返回只属于复位前的诊断初始化，不能证明之后HS视频的画质。录像确认V0.10，FB/BG白同位置暗带、文字和几何角块重复仍在。

联网对照Linux和U-Boot的STM32 LTDC驱动，GCR bit29=1用于物理DE低有效，而SSD2828要求HACT期间DEN高；旧日志GCR=20002221。ST F429官方BSP同样使用DEPolarity=AL。HAL命名与RM0090的NDE定义容易误读，本版只修这项极性，目标GCR=00002221；不改像素格式、时钟、porch、桥B6=2008、DSI400Mbps/2lane、PD6 OD/NOPULL或39包。

VEN开启前各采样120ms：`[DE-PAD] phase=generated`记录生成配置；`phase=ssd2828`记录修正后。用CPSR在宽有效区与垂直后肩选点读取PF10输入逻辑，丢弃边界/跨行/延迟样本。未改IOC时预期ACTIVE-LOW→ACTIVE-HIGH；若IOC已AL，两次ACTIVE-HIGH正常。INSUFFICIENT/PIN-CONFIG/MIXED不能视为通过；采样仅为MCU引脚逻辑证据，不是桥输入端电压/边沿测量。采样在桥VEN=0时进行，不热切运行画面。

烧录带V0.11的Release HEX并校验，整板断电5秒后上电。先保持现有旧板原屏/R11110k/R11922欧/外部10k上拉，比较同硬件下DE单变量；普通8页各4秒，记录全BOOT/DE-PAD/PANEL-READ到第二次B01及约34秒显示视频。重点比较两白页暗带与第8页四角，07单像素竖线是测试图案。若DE逻辑正确而画质未变，停止猜参数，转桥输入波形/HS接收和电源瞬态取证。

约1.4V只为短时诊断条件；单变量验证后，断电将R119单独恢复原设计0欧并测R119/R36约1.8V、R120约1.2V，再重复同固件。GC9503V公开手册IOVCC最低1.65V；R119后的U8输入也受压降影响。额定供电、复位兼容、冷启动和真实30分钟稳定性仍须验收。全部编译/主机测试通过不等于实板画质已修好。未操作CubeMX/烧录器，未提交推送。

## V0.06外部上拉与上板测试（历史基线）

先不接屏、不接上拉，烧录并校验V0.06。完全断电后，在R36/屏座16脚RESET网与本板R119的1V8网（屏座29脚）之间接一只4.7kΩ电阻，R36保留0Ω；不要用导线把RESET直接短接1.8V，也不要上拉到3.3V或2.8V。优先使用本板受控屏1.8V，不用独立常供电源。

先不接屏上电，待启动约20秒后测R36两端应约1.8V；确认后完全断电，再接原屏重新上电，记录RESET电压和画面。复位断言时应低；高电平是开漏释放后由电阻建立。不要把PD6的IDR读低作为1.8V输出失败依据，主控3.3V域数字输入阈值不同。此实验接线只配合V0.06开漏包，不回烧旧推挽包。

启动日志应为`[BOOT] H863 V0.06:`，随后`[RESET] PD6 mode=1 type=1 pull=0 latch=0`。这是GPIO初始化后的寄存器状态，此时RESET保持低；不是电压测量或屏端接收证明。启动后依然无图时先保留全串口及R36实际电压，不盲目调整视频/厂家参数。

复位后先等待完整SDRAM自检和SSD2828 ID=2828三次/寄存器恢复通过，再进行面板初始化和两种边沿测试。每组16页，各10秒，每组约160秒，两组约320秒：

1. 大A/B身份页、白、红、绿、蓝。
2. 16级灰阶、RGB原生阶梯、16个像素数据位及反相、32/4像素棋盘、1像素竖/横线、四角/粗边框几何。
3. 第14页FB白色参考，第15页无图层的BG全白，第16页结束身份卡。

先A/RISING（桥B6=0008、一块标记），后B/FALLING（B6=2008、两块标记），随后循环。FB页前144行显示黑白身份栏和两位页号；BG15不叠加身份栏、不读写帧。其余CubeMX时序、DSI速率和面板命令保持。每张FB先禁图层并确认VBlank提交，再写帧并提交启用。切边沿先清B7 bit3（VEN），回读B6后恢复视频。

从复位开始录约6分钟，比较A/B的灰阶、细节和第14/15页白色，保存完整新日志。UART5：适配器RX接PC12、GND共地、115200/8N1/无流控。每页静态10秒和切换短暂变黑属于预定行为；1像素线在手机缩图/拍摄中可能产生摩尔纹，结合裸眼和大棋盘判断。

串口每秒ALIVE，记录STEP/EDGE、C6/C7等16寄存器、两图层BFCR/DCCR状态和帧哈希。探测失败前记录GPIO输入逻辑值，随后关电；GPIO值不是电压测量。ID全FFFF/0000时不进入图案，先查桥控制、电源、复位和连线，不能靠调屏格式修复。检测到扫描、切换/回读、混合状态或帧变化错误时停止显示并关电。`ERRORS`仅是显示诊断计数，`BRIDGE=FAIL`时即使ERRORS0也不是正常；`INIT-SENT`和帧哈希不变不代表面板接受或画面通过。

V0.04曾只修改BFCR/DCCR寄存器，HAL_LTDC_SetAddress_NoReload会调用LTDC_SetConfig，把缓存的0405写回，再触发diag-layer-state。V0.05同步缓存，预期两层BFCR始终0607、DCCR为0，并越过第一页继续STEP2/16。接屏与否不能由现有日志可靠判断：读到2828的是主板桥接器，屏座LCD-ID在原理图标NC，当前无面板ID/状态回读。`INIT-SENT`在未接屏时也可能出现。
